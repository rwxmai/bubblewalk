## Save layout

All addresses below are image RVAs. Let F point at hardware-saved RIP in the active handler stack.

```text
KiNmiInterrupt: 0x666FC0
  sub rsp,8
  push rbp
  push rsi
  sub rsp,150h
  lea rbp,[rsp+80h]

  body RSP = F-168h
  body RBP = F-E8h
```

The volatile saves begin at RVA `0x666FD9`:

```text
RAX=[RBP-50h] RCX=[RBP-48h] RDX=[RBP-40h]
R8 =[RBP-38h] R9 =[RBP-30h] R10=[RBP-28h] R11=[RBP-20h]
```

At RVA `0x667186`, `XOR ESI,ESI` destroys the original RSI value in the live register. Recover original RSI from `F-0x18`; original RBP is at `F-0x10`.

At RVA `0x667229`, `CALL KxNmiInterrupt` stores return RVA `0x66722E` at `F-0x170`.

```text
KxNmiInterrupt: 0x667440
  sub rsp,138h
  lea rax,[rsp+100h]
  ... save XMM6..XMM15 ...
  mov [rax+00h],rbx
  mov [rax+08h],rdi
  mov [rax+10h],rsi
  mov [rax+18h],r12
  mov [rax+20h],r13
  mov [rax+28h],r14
  mov [rax+30h],r15

  body RSP = F-2A8h
  save RAX = F-1A8h
```

Kx's RSI save is handler RSI, not interrupted RSI. The other listed GPRs retain the interrupted values across Ki's ordinary ABI calls. RBP/RSI are recovered from Ki's earlier pushes.

At RVA `0x6674BD`, `CALL KiProcessNMI` stores return RVA `0x6674C2` at `F-0x2B0`. The callback dispatcher lies inside KiProcessNMI. Both return slots must match before fixed save offsets are accepted.

## Unwind metadata

| Routine | Begin / end RVA | Unwind RVA |
| --- | --- | --- |
| KiNmiInterrupt | `0x666FC0 / 0x66741D` | `0xB6328` |
| KxNmiInterrupt | `0x667440 / 0x667522` | `0xB6348` |

Both records use unwind version 2. Ki's record includes SET_FPREG, stack allocation, RSI/RBP pushes, epilogue descriptors, and PUSH_MACHFRAME. Kx's record includes SAVE_NONVOL for RBX/RDI/RSI/R12–R15, SAVE_XMM128 for XMM6–XMM15, stack allocation, and an epilogue descriptor.

Recovery reads the captured saves directly. DbgHelp starts at interrupted RIP/RSP with the recovered integer register set. Handler unwind metadata is supporting evidence for the layout, not the mechanism used to seed the interrupted chain.

## Identity gates

Driver initialization compares runtime PE size/timestamp/checksum and five instruction ranges with `include/target_26100_1.h`: Ki's prologue, Ki's volatile saves, Kx's prologue/save sequence, and the two CALL sites. These NMI ranges must match exactly. It also checks the nine IOCTL instruction ranges in `include/ioctl_26100_1.h`, with the two runtime exceptions below handled by `include/ioctl_runtime_26100_1.h`. The analyzer requires the original bytes in the archived PE for all fourteen ranges. Capture additionally checks the active gate/TSS interpretation and frame geometry. Recovery checks both return slots and all captured machine-frame fields.

### Loader function overrides

The pinned kernel's Dynamic Value Relocation Table contains a function override for the dispatch thunk at RVA `0x664660`, with replacement RVAs `0xB57780` and `0xB577E0`. Its relocation records explicitly identify the four-byte call displacements at `0x32BF19` and `0x870000`. Windows can rewrite these calls when loading the same kernel file; a matching file hash and version therefore do not imply identical runtime bytes at these locations.

| Call site | CALL RVA | Return RVA | Accepted runtime target RVAs |
| --- | --- | --- | --- |
| `IofCallDriver` dispatch | `0x32BF18` | `0x32BF1D` | `0x664660`, `0xB57780`, `0xB577E0` |
| Fast device control dispatch | `0x86FFFF` | `0x870004` | `0x664660`, `0xB57780`, `0xB577E0` |

The driver permits only these targets at these two CALL sites. Each CALL must retain its `E8` opcode and five-byte length; every other byte in each checked range must match the pinned profile. Return PCs and stack layout checks remain unchanged. The archived-file matcher stays strict because the loader overrides are runtime transformations.

### Load diagnostics

`sc.exe start Bubble` can report error 1306 when initialization returns `STATUS_REVISION_MISMATCH`. Read the driver's `Bubble:` debug output to distinguish the build/profile check from kernel identity, NMI instruction, or IOCTL instruction validation. Instruction failures report the range's starting RVA so it can be compared with the corresponding profile entry.

With a kernel debugger attached, enable the driver's error messages before retrying the service start:

```text
ed nt!Kd_IHVDRIVER_Mask 1
```

The runtime override handling is covered by constructed byte-range tests. A successful Windows driver load and live NMI capture must still be verified in the guest.

These gates select one layout. They do not authenticate every kernel byte or prevent changes after driver initialization. A KVA-shadow path that moves the active frame outside the captured IST arrangement fails the geometry or return-slot checks. User contexts, alternate thread stacks, truncated IST snapshots, and nested entry are not reconstructed by this profile.

The kernel's exception directory also contains an empty range and a nonempty range in INITDATA without the execute flag. The PE reader accepts their structural presence. Empty ranges are omitted from lookup; executable-address classification remains a separate check.

## Reproduce static inspection

Run the included standard-library inspector against the downloaded files:

```powershell
python scripts/Inspect-Target.py C:\symbols\ntoskrnl.exe C:\symbols\ntkrnlmp.pdb
```

With LLVM tools, inspect the save code and unwind records:

```text
llvm-objdump -d --start-address=0x140666fc0 --stop-address=0x140667522 ntoskrnl.exe
llvm-objdump --unwind-info ntoskrnl.exe
```

The disassembly uses the file's preferred image base `0x140000000`. Runtime comparisons add the recorded loaded base to each RVA.
